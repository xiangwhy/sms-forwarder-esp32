# v4.0.23 撤回 — FW v4.0.22 维持生产

## 决策

**翔哥 2026-06-22 拍板: v4.0.23 不烧, FW v4.0.22 维持当生产.**

跟 [[dtac-gateway-anomaly]] 2026-06-20 "不要扩 sniff" 警告一致 — v4.0.23 是删 sniff 走 AOSP 严格丢 body 路径, 跟 device v4.0.22 (Boot #128) 行为有本质差异 (现在给乱码, 未来给空 body), 不符合 "功能稳不动" 原则.

## 撤回原因

1. **真机复现 dtac 乱码 ≠ device bug** — v4.0.22 +66813079348 复现乱码 (希腊/拉丁字母) 经查跟 v4.0.20 同源 (DTAC gateway 偶发 raw UD bytes 异常). v4.0.22 SCA 部分修后 dtac gateway 仍会偶发推送异常, v4.0.23 丢 body 是"严格但空", v4.0.22 是"乱码但有内容", 翔哥 接受后者 trade.

2. **v4.0.23 fixture A 期望调整 = 行为破坏** — 撤回 fixture A adjust commit `726124d` (翔哥 2026-06-22 拍板撤回 50bda13 决策). v4.0.23 实施后 fixture A 会从 "SCA leak check + n>30 PASS" 变 "bodyN=0 FAIL" (case 3 触发: UDH 7 字节污染 + 字节对齐偏移 → 7-bit decode 不 strict UTF-8 → drop body). 翔哥 接受此 trade 但留 **v4.0.24+** 修 (不现在动).

3. **sniff helper 不删 = spec 留历史 reference** — `looks_like_ucs2_be` / `is_strict_utf8` / `pdu_ud_offset_ex` 仍在 pdu_codec.cpp, 留供未来"如果业界行为变更"重启用. 不动 pdu_codec.

4. **8 commit 不 revert** — git commit 是历史 reference, spec 跟 TDD red fixtures 跟 注释 fix 跟 spec+plan amend 6 commit (50bda13/985bdf4/e0af3ca/b8fb50c/e4eb4b6/8165bb3) 保留 main branch, 文档化 v4.0.23 工作 + 撤回原因, 不 git reset.
